API gaps and open questions

Nothing here is faked in the mockups; each needs an owner or API decision.

  1. Retry time on 429. The 429 body is {"message","code":"TOO_MANY_REQUESTS","errors":{}} with no time. The app needs the Retry-After header on every 429, and in the browser CORS must expose it (Access-Control-Expose-Headers: Retry-After), or the body should carry errors.retry_after.
  2. Web push. Decision 10.4 needs a web-push subscription endpoint; POST me/devices is FCM-only today (already noted in decision 0001).
  3. Unread count for the bell. unread_count comes only with the GET me/notifications list. Fine if the list is cheap; otherwise add it to /me.
  4. Category icons. category.icon holds Material names (e.g. local_car_wash); shadcn/KokonutUI use Lucide. The app needs a mapping table (no API change), or the API could send an icon key that is library-neutral.
  5. Standing on the applicant list (plan conflict, not an API gap). BUILD_PLAN U4 says the applicant list shows standing; spec §6 and the API keep standing private (only /me). Decision 8 follows the spec. Which is right?
